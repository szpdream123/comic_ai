# 生产发布：防止构建权限错误导致 502

2026-09-07 故障：服务启动时 esbuild 覆盖 `.production/chunks` 中的文件，部分文件属于 `root:root` 且权限为 `0644`，运行账号无法写入。启动失败后 PM2 连续重试，4310 未监听，Nginx 返回 502。

## 构建和发布边界

- `package-project.ps1` 在打包前构建后端和前端；任一构建失败就终止打包。
- 前端启动构建先在内存中完成编译，按字节比较已有产物；相同文件直接复用，不覆盖只读文件。
- 新产物用同目录临时文件写入，再重命名发布，全部产物成功后才更新 manifest。保留旧 hash 文件，供已经打开的页面继续使用。
- 仍然执行编译，以检测源码与依赖变化，不能用“已有 manifest 就跳过”代替验证。本改动不取消数据库迁移、环境读取或后台任务的启动检查。
- 安全替换要求产物目录对运行账号可写；代码不会自动提权、修改属主或放宽整个项目的权限。

## 每次发布

1. 使用独立的新版本目录解压，保留上一版。依赖安装、构建统一使用服务运行账号，不交替使用 root 和 www 生成文件。若由 root 解压，在新版本目录内按既有运行账号修正属主，不能对 `/www` 整体执行递归改权限或使用 `777`。
2. 配置使用服务器正式 `.env`，不随 ZIP 分发。保留原有数据库、上传目录、日志目录等配置。生产 PM2 的工作目录必须指向实际含 `package.json` 的发布目录。
3. 在新版本目录中，以服务运行账号运行 `node scripts/build-production-web.mjs` 和 `node scripts/build-production-runtime.mjs`，构建成功再切换。当前实例的运行账号和 Node 路径应从 PM2 配置确认，不凭 root 终端的 PATH 推断。
4. 使用现有 PM2 管理入口重启 `comic-ai`，不要另外运行 `npm start` 创建第二套服务。观察运行时间及重启计数，并验证后端和域名访问；仅显示 `online` 不代表服务已就绪。
5. 健康检查失败时恢复上一版代码目录及 PM2 工作目录；数据库迁移是否可回退需另行评估，不直接回滚数据库。旧版本及 hash 产物不要在发布时立即清理。

当前实例的检查命令（只读）：

```bash
pm2 ls
pm2 logs comic-ai --lines 30 --nostream
ss -lntp 'sport = :4310'
curl --max-time 10 -sS -o /dev/null -w 'backend HTTP %{http_code}\n' http://127.0.0.1:4310/
curl --max-time 15 -sS -o /dev/null -w 'site HTTP %{http_code}\n' https://lingxiyunai.com/
```

确认连续稳定后，在原 PM2 管理账号下执行 `pm2 save` 保存配置。

## 防止重启风暴

在现有 PM2 应用配置中设置启动失败重试边界，例如 `min_uptime: "30s"`、`max_restarts: 5`、`exp_backoff_restart_delay: 1000`。保留既有 `cwd`、运行账号、环境变量和日志设置，不另建同名 PM2 实例。上述阈值只限制短时间启动失败，不能替代网站健康监控；进程停止、重启计数持续增加或域名连续 5xx 时应告警。

这些 PM2 设置需要在服务器实际配置中应用，本地代码变更不会自动更改服务器配置。
