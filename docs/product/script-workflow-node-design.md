# 剧本工作流节点设计

## 目标

在画布中提供一个可复用的“脚本工作流节点”（下文简称“脚本节点”）。脚本节点接收正式剧本，负责把正式剧本拆分为角色、场景、道具和分镜，并控制后续图片、视频节点；小说转剧本由脚本节点创建的现有 AI 文本节点完成，不把小说原文直接当作拆分输入。

用户可以为同一个画布放置多个脚本工作流节点。每个节点只影响从自身发出的链路，不与其他脚本混用内容、资产或生成结果。

## 核心原则

1. 一个脚本节点对应一个创作上下文，并保存当前确认的正式剧本。
2. 一个剧本可拆出多个角色、场景、道具与分镜。
3. 剧本可派生多个角色、场景、道具生图节点和多个分镜生视频节点；每一个节点都是可独立编辑、运行和删除的画布节点。
4. 角色、场景、道具节点先生成各自的参考图；分镜视频节点通过 `@角色`、`@场景`、`@道具` 引入实际参考图生成视频。
5. 一个分镜可生成多个视频版本，所有分镜视频可按脚本节点范围统一批量导出或下载。
6. 画布节点始终可手动添加、连接、修改、复制和删除；工作流快捷操作只负责减少重复搭建。
7. 修改正式剧本后，下游节点下一次运行应读取该脚本节点的当前内容；已经生成的媒体保留为历史结果，不被自动覆盖或删除。
8. 小说模式的固定顺序是“小说输入 -> AI 文本剧本生成节点 -> 正式剧本同步到脚本节点 -> 脚本节点拆分”；角色、场景、道具、分镜不得直接读取小说原文。

## 节点结构

### 脚本工作流节点

节点固定提供三个剧本来源，切换来源不删除已经存在的下游节点。

| 来源 | 用户输入 | 输出 |
| --- | --- | --- |
| 选择剧本 | 从项目剧本库选择剧本和章节 | 正式剧本文本写入脚本节点 |
| 自己填写 | 直接输入剧本、对白、动作和镜头说明 | 正式剧本文本写入脚本节点 |
| 小说生成 | 输入小说片段、梗概或人物设定 | 创建一个独立可运行的“剧本生成”AI 文本节点；其成功结果同步为脚本节点的正式剧本 |

脚本节点本身保存当前正式剧本，并通过一个通用文本输出端口向拆分后的节点提供该剧本。小说模式下，AI 文本节点的成功结果通过脚本工作流同步逻辑写入脚本节点；同步只更新脚本节点文本，不重载画布、不移动节点，也不自动开始拆分或生成。角色、场景、道具和分镜均以独立下游节点表达，避免固定结构限制复杂项目。角色、场景、道具节点是生图节点，其输出图片即该资产的参考图；分镜节点是生视频节点。生视频节点只接收分镜提示词中明确出现的 `@资产` 引用，不能仅凭同属一个脚本节点自动带入全部资产。

脚本节点同时是这些下游节点的控制入口。点击“打开脚本节点”后进入脚本工作区，可集中查看、修改、创建、删除和运行所属的图片与视频节点。工作区不是另一套数据，也不复制子节点内容；它只是同一画布节点数据的结构化视图。

节点内显示四段状态：

```text
剧本 -> 资产 -> 分镜 -> 成片
```

状态只显示已创建数量，例如“角色 3、场景 4、道具 8、分镜 12、视频 18”。数量来自实际下游节点和视频结果，而不是单一覆盖字段。

### 脚本工作区

打开脚本节点后，以覆盖画布的工作区展示三个阶段，但不调用浏览器原生全屏：

1. **确认镜头**：以表格展示所有分镜视频节点，包含镜号、时长、画面描述、景别、光影氛围、对白/旁白、音效、运镜、最终视频提示词和操作。新增、删除或修改一行，就是新增、删除或修改对应的画布分镜视频节点。
2. **准备资产**：按角色、场景、道具分区展示所有资产生图节点。每一项直接显示该节点的提示词、参考图结果、生成状态和版本；支持单项生成、上传、重试、新增、删除以及批量生成全部缺失参考图。
3. **合成提示词**：逐条展示分镜视频节点的最终提示词和 `@角色/@场景/@道具` 引用。引用选择器只列出当前脚本节点所属的资产生图节点；确认后写入对应视频节点的提示词引用文档。

工作区顶部提供“重新解析剧本”“批量生成资产参考图”“批量生成分镜视频”和“批量导出/下载”操作。按钮只作用于当前脚本节点所属的子节点。

### 单一数据源与双向同步

脚本工作区中的每一个角色、场景、道具和分镜项，都必须对应画布上的一个真实节点 ID。脚本节点只保存子节点成员关系、顺序和阶段状态，不保存子节点提示词、模型参数或生成结果的副本。

```text
脚本节点
  └─ childNodeIds
       ├─ role-node-1   -> 画布 AI 图片节点
       ├─ scene-node-1  -> 画布 AI 图片节点
       ├─ prop-node-1   -> 画布 AI 图片节点
       └─ shot-node-1   -> 画布 AI 视频节点
```

双向同步遵循以下规则：

1. 在脚本工作区内修改内容时，直接调用现有画布节点更新能力，更新对应子节点的数据；关闭工作区后，外部节点立即显示新内容。
2. 在画布外部修改子节点提示词、模型、参数、参考图或生成结果时，脚本工作区读取同一画布文档并立即显示变更。
3. 在脚本工作区新增角色、场景、道具或分镜时，必须实际创建对应的外部图片或视频节点，并把新节点 ID 加入当前脚本节点成员关系。
4. 在脚本工作区删除子项时，实际删除对应外部节点及连线；在外部删除子节点时，脚本工作区同步移除该项和失效引用。
5. 在内部调整分镜顺序时，只更新脚本节点保存的子节点顺序和分镜编号，不复制或重建视频节点。
6. 内外同时编辑同一节点时，以画布文档的节点修订号进行乐观并发检查；检测到较新外部版本时，工作区先刷新，不静默覆盖。
7. 内外同步只触发局部节点和工作区视图刷新，不重载整个画布，不改变节点位置，也不重新运行任何生成任务。

脚本节点与子节点的关系是控制关系，不是内容复制关系。所有生成、上传、重试、下载仍调用对应图片或视频节点的现有动作，因此脚本工作区关闭后，子节点仍可独立使用。

### 可执行组边界

每一个脚本工作流节点同时定义一个可执行组。它只收纳 `workflowParentId` 等于自身 ID 的真实画布节点，并以正式剧本进入脚本节点作为拆分入口、批量下载作为出口：

```text
小说输入 -> AI 文本“剧本生成”节点 -> 正式剧本 -> 脚本节点
已选剧本 ---------------------------------------> 脚本节点
手写剧本 ----------------------------------------> 脚本节点
  -> 按所选技能拆分剧本
  -> 角色、场景、道具生图节点
  -> 分镜视频节点（依赖其 @ 引用的参考图）
  -> 当前脚本工作流的视频结果
  -> 批量下载 / 导出
```

执行顺序由真实画布连线和 `@` 引用依赖决定，而不是节点在画布上的位置：

1. 小说模式先运行 AI 文本“剧本生成”节点；成功结果同步到脚本节点并成为当前正式剧本。选择剧本和手写模式直接把正式剧本写入脚本节点。
2. 用户确认脚本节点中的正式剧本后，脚本节点调用角色、场景、道具、分镜四类技能进行拆分，并为返回的每一项创建一个真实画布节点。
3. 角色、场景、道具生图节点可以并行执行。
4. 每个分镜视频节点只在其全部 `@` 引用资产均生成可用参考图后执行；不同分镜可并行执行。
5. 批量下载只在组内已有成功视频结果时可用，收集该组全部或用户选定的分镜视频版本。

组运行只提交当前组内的可运行节点及它们的依赖，不扫描、等待、运行或下载其他普通画布节点。单个子节点失败只标记该节点及其下游分镜为阻塞，不中断没有依赖它的其他资产和分镜。

## 快捷操作

脚本节点内提供以下快捷操作。每次执行都创建新的普通画布节点，不覆盖既有结果。

| 操作 | 创建的节点 | 默认连接 |
| --- | --- | --- |
| 生成剧本 | AI 文本：剧本生成 | 小说输入作为提示词；成功结果同步到脚本节点的正式剧本 |
| 解析并创建节点 | 多个角色、场景、道具 AI 图片节点和多个分镜 AI 视频节点 | 脚本节点中的正式剧本 -> 四类技能 -> 每条返回数据对应一个真实节点 |
| 生成角色节点 | 多个 AI 图片：角色生图节点 | 脚本节点 -> 每个角色生图节点；输出角色参考图 |
| 生成场景节点 | 多个 AI 图片：场景生图节点 | 脚本节点 -> 每个场景生图节点；输出场景参考图 |
| 生成道具节点 | 多个 AI 图片：道具生图节点 | 脚本节点 -> 每个道具生图节点；输出道具参考图 |
| 生成分镜节点 | 多个 AI 视频：分镜生视频节点 | 脚本节点 -> 每条分镜视频节点；节点内包含分镜提示词 |
| 在分镜中引用资产 | 为分镜提示词添加 `@角色`、`@场景`、`@道具` | 从同一剧本工作流下的资产生图节点选择实际参考图并注入视频请求 |
| 批量导出分镜视频 | 视频导出任务或下载包 | 收集当前剧本工作流下所有成功的视频结果 |

角色、场景、道具生图以及分镜生视频都没有数量上限。用户可以为同一资产建立多个候选参考图节点，也可以为同一分镜建立多个视频节点或重复运行同一节点产生多个版本。

## 资产与分镜数据关系

角色、场景、道具是独立的生图节点集合。每个节点的图片输出就是可被分镜引用的参考图；分镜通过提示词中的 `@资产名` 引用对应节点，解析后把该节点的图片作为视频模型的参考图输入，而不仅是将资产名拼进提示词。

```text
脚本节点中的正式剧本
  ├─ 角色生图节点：@主角 -> 角色参考图 A
  ├─ 场景生图节点：@街道 -> 场景参考图 A
  ├─ 道具生图节点：@信件 -> 道具参考图 A
  └─ 分镜视频节点
       ├─ 镜头 01："@主角 在 @街道 读取 @信件" -> 引入三张参考图 -> 视频 A、视频 B
       ├─ 镜头 02："@反派 在 @室内 举起 @武器" -> 引入三张参考图 -> 视频 A
       └─ 镜头 03："@主角 站在 @天台" -> 引入两张参考图 -> 视频 A、视频 B、视频 C
```

分镜视频节点的提示词至少包含：镜号、时长建议、景别、机位、人物动作、对白/旁白、视频运动提示词，以及明确的 `@角色`、`@场景`、`@道具` 标记。每一条分镜的可运行状态由“视频提示词 + 全部可解析的 @ 资产引用”共同构成。用户可手工补充或替换普通提示词，但不得在运行前移除必须的一致性资产引用。

### 参考图传递规则

1. 角色、场景、道具均由各自的 AI 图片节点生成参考图；同一资产允许建立多个生图节点或多次运行，以保留多个版本。
2. 分镜视频节点中的 `@资产名` 只能解析到同一剧本工作流下、同类别且具有可用图片结果的节点。名称相同或不唯一时，用户必须在引用选择器中明确绑定节点 ID。
3. 每次解析 `@` 引用后，视频请求保存“引用标记 -> 资产节点 ID -> 参考图 ID”的快照；名称改动不应静默替换已绑定的参考图。
4. 运行分镜视频前，所有 `@` 引用都必须解析成功并具有有效图片结果；任一引用缺失、尚未生图或图片被删除时，该分镜显示“参考图缺失”且禁止运行。
5. 分镜视频节点把解析到的全部参考图作为多张图片参考输入，同时提交视频提示词。分镜视频结果可以作为同一分镜后续视频版本的可选首帧参考，但不能取代任何 `@` 资产参考图。

### 后端参考图编译规则

画布中使用的 `@主角`、`@街道`、`@武器` 是便于用户识别和编辑的语义标记，不能直接原样发送给视频模型。提交任务前，后端必须把语义引用编译为模型实际使用的“图1、图2……”及同序参考图数组。

例如画布中的分镜提示词为：

```text
@主角 在 @街道 拿起 @武器，镜头从中景推进到近景。
```

解析后的绑定为：

```text
@主角 -> 角色节点 role-1 -> 参考图 asset-role-a
@街道 -> 场景节点 scene-1 -> 参考图 asset-scene-a
@武器 -> 道具节点 prop-1 -> 参考图 asset-prop-a
```

后端发送给模型的内容应等价于：

```text
prompt: 图1中的主角在图2中的街道拿起图3中的武器，镜头从中景推进到近景。
referenceImages:
  1. asset-role-a
  2. asset-scene-a
  3. asset-prop-a
```

编号和图片数组必须遵守以下规则：

1. 按分镜提示词中 `@` 引用首次出现的先后顺序分配“图1、图2……”。
2. `referenceImages[0]` 必须对应图1，`referenceImages[1]` 必须对应图2，后续依次类推，禁止排序后错位。
3. 同一绑定在提示词中重复出现时复用原编号，不重复添加图片。例如第二次出现 `@主角` 仍编译为“图1中的主角”。
4. 同名资产绑定到不同参考图时视为不同引用，必须分别编号；前端应显示具体版本，避免用户误判。
5. 编号由后端根据已保存的节点 ID 和参考图 ID 重新计算，不能信任前端提交的“图N”文本。
6. 后端保存原始语义提示词、编译后模型提示词、有序参考图 ID 列表和引用映射快照，便于任务重试与问题追踪。
7. 不同视频模型如果要求不同的图片引用语法，由模型适配层把统一的有序引用转换为该模型格式，但图片顺序和绑定关系不得改变。

## 编辑、删除和复用规则

### 修改

- 脚本节点可修改来源、章节或正式剧本文本。
- 每个角色、场景、道具生图节点和分镜视频节点都可以独立编辑提示词、模型和参数；分镜中的 `@` 引用通过专用选择器修改，不靠自由文本猜测。
- 修改上游剧本后，资产生图节点和分镜视频节点再次运行时读取新的上游文本；已解析的 `@` 绑定不会被自动替换，已生成的图片和视频也不会自动改变。
- 用户需要保留旧版本时，复制脚本节点及其下游节点后再修改，形成并行版本链路。

### 删除

- 删除任何角色、场景、道具生图节点或分镜视频节点，只移除该节点和与它相连的边；被分镜引用的参考图依照“参考图缺失”规则处理。
- 删除脚本节点时不应隐式删除下游结果，避免误删已经生成的内容；画布应保留这些节点供用户重新连接或手工删除。
- 脚本节点的进度数量基于仍存在的下游节点计算，删除后立即更新。

### 复用

- 同一脚本节点可被多个角色、场景、道具生图节点和分镜视频节点重复连接；同一个资产参考图也可被多个分镜视频节点通过 `@` 引用复用。
- 多个脚本节点可并存，例如“第一集”“第二集”“宣传短片版本”。
- 下游节点记录其所属脚本节点 ID，仅用于画布分组、统计和快捷操作；实际生成仍依赖明确的画布连线。
- 不允许快捷操作跨剧本自动引用最近节点，防止不同剧本的角色、场景、图片或视频串用。

## 交互与状态

### 节点尺寸

脚本节点应比普通来源节点更大，能在节点内完成剧本来源、正式文本预览、链路状态和快捷操作。它不使用浏览器全屏，不遮挡画布拖动和缩放。

### 可用状态

| 条件 | 可用操作 |
| --- | --- |
| 尚未输入/选择剧本 | 选择剧本、自己填写、小说生成 |
| 已输入小说梗概 | 创建并运行 AI 文本“剧本生成”节点 |
| AI 文本“剧本生成”节点成功 | 将结果同步为脚本节点的当前正式剧本 |
| 脚本节点已有正式剧本文本 | 选择四类技能，解析并创建多个角色、场景、道具生图节点和分镜视频节点 |
| 角色、场景、道具节点已有图片结果 | 在分镜提示词中添加并绑定相应的 `@` 引用 |
| 分镜提示词中的全部 `@` 引用可解析且均有图片结果 | 生视频 |
| 当前剧本工作流下存在成功的视频结果 | 批量选择、批量下载或导出全部分镜视频 |

生成失败、模型未配置或积分不足时，错误状态显示在具体生成节点上，不影响脚本节点内容和已经生成的其他节点。

## 实施边界

第一阶段只做画布工作流编排与现有生成节点复用：

- 本质上只新增一个“脚本工作流节点”。该节点接收正式剧本，负责解析剧本、创建并组织现有角色/场景/道具生图节点和分镜生视频节点，不创造第二套生成体系。
- 小说转剧本必须复用现有 AI 文本节点和接口；AI 文本结果成功后仅同步到脚本节点，再由脚本节点调用四类技能拆分，禁止让下游素材或分镜直接读取小说原文。
- 角色、场景、道具继续调用现有 AI 图片节点及现有生图接口；分镜继续调用现有 AI 视频节点及现有视频接口；剧本生成继续调用现有 AI 文本节点及现有文本接口。
- `@资产` 继续复用现有画布提示词引用机制。新增逻辑只负责在分镜视频提交前生成有序引用快照和“图1、图2……”映射，不改变其他生图、生视频节点的提示词处理。
- 批量导出只汇总当前剧本工作流所属的现有视频结果并调用现有下载能力，不修改全局生成历史、资产库和普通视频节点的下载行为。
- 所有新增数据均挂在脚本节点或由它创建的下游节点上，并通过所属脚本节点 ID 隔离；普通画布节点没有这些字段时，行为必须与改动前完全一致。
- 新功能开关、事件处理、样式和节点尺寸仅作用于剧本工作流节点，禁止修改其他节点的默认尺寸、拖动、全景、分镜切图、文本编辑、生成和刷新行为。
- 不新增后端数据结构或新模型接口。
- 不改变已有剧本库、资产库、文本、生图、生视频的接口契约。
- 不将多个图片/视频塞进单个节点数据字段。
- 不自动执行整条链路；用户需依次确认角色/场景/道具参考图、分镜视频提示词和每条分镜的 `@` 引用解析结果后再运行，便于检查一致性。

### 非回归要求

实现和验收必须覆盖以下隔离条件：

1. 未添加剧本工作流节点的旧画布，保存、加载和运行结果保持不变。
2. 手工创建的普通文本、生图、生视频节点仍按原逻辑运行，不自动获得剧本关系或 `@` 编译行为。
3. 删除剧本工作流节点不删除现有资产和媒体结果，只解除其编排关系。
4. 一个剧本工作流的快捷操作不能读取、修改或导出另一个剧本工作流的节点和结果。
5. 新节点异常、引用缺失或批量导出失败时，只影响当前剧本工作流，不阻断画布其他节点。
6. 实施测试以脚本节点新增链路为主，同时回归普通生图、生视频、文本节点、全景预览、图片切分和画布拖动。

### 双向同步验收

1. 在脚本工作区修改一个角色提示词，关闭工作区后，对应外部 AI 图片节点显示完全相同的提示词。
2. 在外部 AI 图片节点更换模型或生成参考图，重新打开或保持打开的脚本工作区能显示新模型、状态和图片结果。
3. 在脚本工作区新增一条分镜，画布出现一个真实 AI 视频节点；外部删除该节点后，工作区对应分镜消失。
4. 在外部修改分镜的 `@` 引用，工作区“合成提示词”同步更新，并按新出现顺序重新预览“图1、图2……”映射。
5. 从工作区运行资产或分镜，生成任务、积分、历史记录和结果节点行为与直接运行外部节点一致。
6. 工作区批量操作只遍历当前脚本节点的子节点 ID，不扫描或修改其他普通图片、视频节点。
7. 内部修改、外部修改和生成状态更新均不得造成整页刷新、画布重载、节点跳位或已生成媒体丢失。
8. 小说转剧本节点无论单独运行还是作为脚本工作流批次运行，成功文本都必须同步到脚本节点；后续“解析并创建节点”只能读取该正式剧本，不得回退读取小说原文。
9. 剧本解析接口必须跳过重复的小说转剧本阶段，只使用角色、场景、道具、分镜四类已选技能；返回的每一条角色、场景、道具、分镜数据都创建一个独立真实节点。
10. 后端收到分镜 `@` 引用时，必须确认目标分镜与每个参考图节点属于同一个脚本节点，并确认指定参考图版本属于对应资产节点；跨脚本引用直接拒绝。

后续阶段可在不改变上述关系的前提下增加“批量运行已选分镜”“分镜资产引用选择器”“版本比较”和“按剧本批量导出视频”。
