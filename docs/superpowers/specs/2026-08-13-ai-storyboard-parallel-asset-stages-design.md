# AI 分镜资产阶段并行优化设计

> Date: 2026-08-13
> Status: Awaiting review
> Scope: 仅优化 AI 分镜预览中场景、角色、道具三个模型阶段的调度方式。

## 1. 目标与边界

当前 `AiStoryboardPreviewService` 按“剧本 → 场景 → 角色 → 道具 → 分镜”串行执行。场景、角色、道具都只依赖已生成的剧本，彼此没有数据依赖，因此可以并行请求模型；最终分镜仍等待三者全部完成后再开始。

本次必须保持：

- 模型、提示词、温度、输出格式和重试规则不变。
- API 请求体、SSE 事件结构、积分计费次数和最终预览结构不变。
- 前端仍按“场景 → 角色 → 道具 → 分镜”的固定顺序接收和展示事件，避免进度乱跳。
- `selectedStages`、跳过剧本阶段、单阶段重新生成、取消和错误返回继续兼容。
- 不修改现有前端文件，不改数据库，不引入长期结果缓存。

## 2. 方案比较

### 方案 A：并行请求并实时交错所有 SSE 事件

三个阶段同时请求，并把事件实时交错发送给前端。速度最好，但当前前端只有一个 `activeStage`，会造成进度标题来回切换，还需要扩大前端改动。

### 方案 B：并行请求，保持事件有序回放（采用）

第一个被选中的资产阶段继续实时流式输出；其余资产阶段同时在后台执行并暂存现有事件。前一个阶段完成后，按原有固定顺序回放已经暂存的事件。所有资产阶段完成并解析后，再生成最终分镜。

该方案的模型请求并行，用户看到的阶段顺序、事件内容和最终结果结构保持不变，改动集中在后端服务与测试。

### 方案 C：把场景、角色、道具合并成一次模型调用

调用次数更少，但会改变提示词、技能边界、解析和计费语义，可能影响输出质量，不符合本次用户无感约束。

## 3. 后端数据流

1. 剧本阶段保持现状，得到 `scriptText`。
2. 根据 `selectedStages` 构造固定顺序的资产阶段列表：`scene`、`character`、`prop`。
3. 如果只选中一个资产阶段，继续走原有串行路径。
4. 如果选中两个或三个资产阶段：
   - 第一个阶段作为前台流，事件立即向 SSE 消费者产出。
   - 其余阶段立即开始消费各自的模型流，把原有事件按顺序暂存在内存中。
   - 前台阶段结束后，按固定阶段顺序回放后台阶段事件并取得各阶段原始文本。
5. 使用与当前相同的解析函数得到 `scenes`、`characters`、`props`。
6. 三类资产全部完成后，使用完全相同的输入生成 `shot` 阶段。
7. 归一化并产出原有 `complete` 事件。

暂存只存在于单次 HTTP 请求生命周期内，不跨请求复用。每个后台阶段的事件和原始文本均受当前请求取消信号约束。

## 4. 错误与取消

- 前台阶段失败：立即取消尚未完成的后台资产阶段，沿用现有错误返回，不启动分镜阶段。
- 后台阶段失败：保存原始错误；轮到该阶段时抛出并取消其余阶段，不启动分镜阶段。
- 用户关闭页面或重新生成：请求的 `AbortSignal` 同时传给所有并行阶段，避免后台继续消耗模型资源。
- 后台 Promise 在创建时立即安装成功和失败处理，避免未等待期间产生未处理拒绝。
- 单个阶段原有“仅在尚未产生输出且错误可重试时重试一次”的规则保持不变。

## 5. 前端与用户体验

前端无需修改。SSE 仍保持：

- 相同事件名和字段。
- 相同的场景、角色、道具展示顺序。
- 第一个阶段继续实时出现内容。
- 后续阶段如果已经在后台完成，会更快显示，但不会交错或覆盖其他阶段状态。

本次不做流式事件合并和跨请求去重。它们对分钟级总耗时收益较小，且需要单独处理断线重连、显式重新生成和事件恢复语义。

## 6. 测试策略

使用现有 `ai-storyboard-preview.service.spec.ts`，按 TDD 增加：

1. 并发启动测试：用受控网关阻塞资产阶段，证明场景、角色、道具请求都已启动，而分镜请求尚未启动。
2. 事件顺序测试：即使后台阶段先完成，消费者仍按 `scene → character → prop → shot` 收到事件。
3. 结果一致性测试：并行后 `displayTables`、`commitPayload` 和 `rawMarkdown` 继续包含全部四类结果。
4. 子集测试：仅选择部分资产阶段时只启动对应请求；只选一个阶段时行为保持原样。
5. 错误测试：任一资产阶段失败时不启动分镜阶段，也不产生 `complete`。

## 7. 验收标准

- 默认流程中场景、角色、道具三个 provider 请求存在时间重叠。
- 分镜 provider 请求只在三个资产阶段全部成功后开始。
- SSE 阶段顺序仍为场景、角色、道具、分镜。
- 模型调用次数、模型代码、提示词文本、计费次数和最终数据结构不变。
- 现有 AI 分镜服务测试及相关 HTTP 测试全部通过。
- 不修改本任务范围外的文件；现有未提交的新手引导改动保持不动。
