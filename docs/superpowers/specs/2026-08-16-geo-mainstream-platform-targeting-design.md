# 灵曦AI GEO 主流大模型平台支持设计

## 背景与目标

现有 GEO 问题记录已经支持 `targetPlatforms: string[]`，后台新建问题时固定写入 `deepseek`、`doubao`、`baidu`，但管理员看不到、不能修改，也无法理解历史值对应的平台名称。

本次第一阶段目标是把国内主流大模型与 AI 搜索平台变成可见、可选择、可持久化的平台目标，为后续“按平台自动提问并统计品牌提及和官网引用”保留稳定的平台标识。第一阶段不登录第三方平台、不调用第三方查询接口，也不承诺自动检测收录。

## 范围

### 第一阶段包含

- 提供统一的 GEO 目标平台注册表。
- 后台问题表单显示平台多选项。
- 默认选择当前启用的全部主流平台，且界面要求至少选择一个。
- 问题列表把已保存的平台标识显示为中文标签。
- 历史 `deepseek`、`doubao`、`baidu` 数据无需迁移即可正常展示。
- 未知的历史平台标识必须保留并以原值展示，不能在编辑或渲染过程中静默丢弃。

### 第一阶段不包含

- 百度、豆包、DeepSeek 等第三方账号接入。
- 模拟网页登录、验证码或反爬绕过。
- 自动向各平台发起提问。
- 自动判断“已收录”、品牌提及率或官网引用率。
- 第三方平台 API 密钥、定时任务和监测报表。
- 数据库结构迁移。

## 架构与组件

### 后端平台注册表

新增一个只负责平台元数据的 GEO 模块，输出只读平台数组。每项只包含稳定 ID、展示名称、分组、是否启用和是否默认选择。该模块不包含第三方凭据或调用逻辑。

超级管理员接口新增 `GET /api/admin/geo/platforms`，沿用现有 `geoManage` 权限边界。接口返回完整平台注册表及启用、默认选择信息，后台不再维护第二份硬编码平台列表。新建表单只展示 `enabled=true` 的平台，列表标签映射则使用完整注册表，因此未来停用的平台仍能正确展示历史名称。

### 现有问题数据

继续使用 `geo_questions.target_platforms_json`，接口仍接收 `targetPlatforms: string[]`。不新增枚举约束，不修改现有方法签名和响应结构。

保存时继续复用现有去重与字符串清洗逻辑。后端保持对空数组和未知值的兼容，避免破坏历史调用；“至少选择一个”只作为本次管理员界面的交互约束。

### 管理后台

GEO 页面加载时，在现有问题、证据、内容、设置请求之外加载平台目录。

“新增问题”表单增加分组复选框：

- 综合大模型
- AI搜索

首次加载时选中平台注册表中 `defaultSelected=true` 的平台。提交时从已选复选框生成 `targetPlatforms`，不再固定写死三个值。若未选择任何平台，阻止提交并给出“至少选择一个目标平台”的明确提示。

问题列表在问题主题下方显示平台标签。已知 ID 使用平台注册表名称；未知 ID 使用原始值，确保历史数据可见。

## 数据流

1. 超级管理员打开 GEO 运营页。
2. 后台请求 `/api/admin/geo/platforms` 并渲染平台多选项。
3. 管理员填写问题并选择目标平台。
4. 前端提交平台 ID 数组到现有问题创建接口。
5. 服务层去重并保存到 `target_platforms_json`。
6. 问题列表根据平台注册表把 ID 映射为标签。
7. 生成服务继续把 `targetPlatforms` 传入写作上下文，为后续平台差异化提示保留信息。

## 失败与兼容处理

- 平台目录加载失败时，GEO 页面显示现有统一错误态，不使用可能过期的前端备用列表。
- 管理员未选择平台时只阻止当前表单提交，不影响页面其他功能。
- 历史未知 ID 不报错、不删除，直接显示原值。
- 已归档或未来停用的平台仍可展示历史标签，但不出现在新建问题的可选列表中。
- 本次不改变 `targetPlatforms` 的 API 类型，因此现有调用方和测试夹具继续有效。

## 第二阶段扩展边界

后续引用监测以相同平台 ID 建立独立能力，不向平台注册表中混入运行状态或监测结果。第二阶段可增加：

- 平台监测方式与可用性配置。
- 固定问题集和执行计划。
- 品牌提及、官网引用、引用页面和答案快照。
- 人工检测与官方 API 检测的来源区分。
- 按平台、问题和时间统计引用率。

没有官方查询 API 的平台不得通过绕过验证码或反爬机制实现自动化，优先使用人工检测或平台明确允许的接口。

## 测试与验收

### 自动测试

- 注册表包含 11 个唯一、稳定的平台 ID。
- `baidu` 的展示名称为“百度文心助手”。
- 管理接口只允许超级管理员访问。
- 后台 HTML 包含平台加载、复选框渲染、至少选择一个的校验和标签映射。
- 新建问题提交所选平台，而不是固定数组。
- 历史未知平台 ID 使用原值展示。
- 现有 GEO 问题创建和内容生成测试继续通过。

### 人工验收

1. 超级管理员进入“GEO运营”。
2. 确认 11 个平台按两组展示并默认选中。
3. 取消部分平台后新增问题，确认列表只显示实际选择的平台。
4. 全部取消后提交，确认出现明确提示且不发送请求。
5. 查看历史问题，确认 `baidu` 显示为“百度文心助手”。
6. 生成草稿，确认原有生成、质检、审核和发布流程不受影响。

## 成功标准

- 管理员能够看见并选择全部约定的国内主流平台。
- 新问题保存的目标平台与界面选择完全一致。
- 历史平台数据无迁移、无丢失、可读。
- 不引入第三方凭据和外部平台调用。
- 为第二阶段引用监测提供稳定且唯一的平台 ID。
