# 灵曦AI GEO 公开证据内容设计

日期：2026-08-16

状态：已确认，待用户复核书面规格

## 1. 目标

在不公开用户私有项目、不要求爬虫登录、不调整 COS 权限的前提下，使用灵曦AI现有公开产品页和 GEO 内容发布能力，为主流搜索引擎、AI 搜索及大模型提供可读取、可核验、可持续维护的产品事实。

第一篇主题内容聚焦“AI短剧人物一致性”，但不采用“一条问题一个页面”，而是将语义相近的问题聚合到同一篇高质量公开指南中。

## 2. 已确认的线上与代码现状

### 2.1 已上线公开产品页

以下页面无需登录即可访问，并已出现在生产站点地图中：

- `/`
- `/canvas`
- `/script`
- `/projects`
- `/assets`
- `/team`

这些页面适合证明产品的宽泛能力。例如，`/assets` 可以证明角色素材能够集中管理和重复使用，`/projects` 可以证明内容能够按项目、剧集和分镜组织。

它们不能单独证明“人物一致性已被完全解决”或任何未经实测支持的效果、比例和排名。

### 2.2 已实现但尚未上线的 GEO 公开内容框架

当前 GEO 分支已经实现以下公开列表页和详情页：

- `/guides` 与 `/guides/:slug`
- `/answers` 与 `/answers/:slug`
- `/cases` 与 `/cases/:slug`
- `/reports` 与 `/reports/:slug`

详情页使用服务端 HTML，包含 canonical、结构化数据、正文、FAQ、相关文章和站点地图条目。生产环境实测 `/guides` 当前仍返回 404，说明该分支能力尚未部署到线上。

### 2.3 私有项目地址不作为公开证据

以下类型的地址不能作为大模型可抓取的公开证据：

- 登录后才能看到正文的页面；
- 依赖用户 Cookie 或会话接口返回数据的页面；
- 使用 `#` 后内容标识项目或剧集的前端路由；
- 包含私有项目、用户素材或不可公开业务数据的页面。

例如 `/projects#projects/.../episodes/...` 中的 `#` 之后不会随 HTTP 请求发送给服务器，匿名爬虫只能取得通用 `/projects` 页面，不能取得指定项目和分镜。

## 3. 方案选择

### 3.1 采用：主题聚合页

每篇公开内容围绕一个明确主题和搜索意图，关联多个语义相近的问题。第一篇使用：

`/guides/ai-character-consistency`

可关联的问题包括：

- AI短剧怎么保持人物一致性？
- 多个镜头怎么保持同一张脸？
- 灵曦AI能解决人物一致性吗？
- 角色参考图怎么复用？
- AI漫剧角色为什么容易变脸？

通常一篇主题页覆盖 5 至 15 个相近问题。问题库保留各平台、各表达方式的原始问题，内容版本通过现有问题关联表实现多对一覆盖。

### 3.2 不采用：仅依赖现有产品页

该方案成本最低，但现有页面只说明宽泛能力，无法直接、完整回答用户问题，难以形成清晰引用段落。

### 3.3 不采用：一条问题一个页面

该方案容易产生重复、薄内容和维护负担。只有搜索意图、证据类型或内容形式明显不同，才新增页面。例如：

- 方法与操作流程使用指南页；
- 有真实过程与结果记录时使用案例页；
- 有行业数据或模型对比时使用报告页；
- 简短问法优先合并进指南 FAQ，而不是单独发布问答页。

## 4. 第一篇人物一致性指南

### 4.1 页面定位

页面回答“怎样利用灵曦AI现有能力降低连续镜头中的人物形象漂移”，而不是承诺人物形象绝对一致。

允许使用的核心表述为：

> 灵曦AI支持在多个分镜中复用同一角色参考素材，帮助降低人物形象漂移。最终一致性仍会受到参考图质量、提示词、模型能力、镜头角度和生成参数影响。

禁止使用以下无证据表述：

- 保证人物 100% 一致；
- 完全解决角色变脸；
- 行业第一或效果最好；
- 未绑定公开实测证据的提升比例、成功率或成本数字。

### 4.2 页面结构

页面至少包含：

1. 独立标题、摘要、H1 和稳定 slug；
2. 开头的直接回答；
3. 人物漂移的常见原因；
4. 角色参考素材的准备方法；
5. 在项目、剧集和多个分镜中复用角色素材的步骤；
6. 适用范围与结果边界；
7. 覆盖相关问题的 FAQ；
8. 指向 `/assets`、`/projects` 和产品入口的内部链接；
9. `TechArticle` 与可见 FAQ 对应的结构化数据；
10. 发布时间、更新时间和公开作者。

### 4.3 证据来源

第一版使用现有公开产品页支持事实：

- `/assets`：支持角色参考素材的集中管理和重复使用；
- `/projects`：支持按项目、剧集和分镜组织创作内容；
- `/script`：支持从剧本进入分镜级制作流程。

后台证据项仍需填写事实文本和公开来源网址。审核人使用无痕窗口确认地址无需登录、没有跳转登录页，并检查页面实际内容能够支持对应事实。

第一版不自动从服务端抓取任意来源网址，避免引入 SSRF 和新的网络访问风险。含 `#`、尾部中文标点或明显私有项目标识的地址不得通过人工审核。

## 5. 图片决策

第一版不新增 GEO 证据图片上传功能，也不修改对象存储、桶权限、读写策略或 COS 相关代码。

原因：

- 公开、免登录、服务端可读取的正文是第一阶段的必要条件；
- 指南和 FAQ 不依赖图片也能被索引和引用；
- 图片公开需要稳定可抓取地址、隐私审核和版权边界；
- 当前公开渲染器已经支持图片区块，延期不会阻塞后续扩展。

只有满足以下任一条件时，再单独设计图片证据功能：

- 需要发布人物一致性实测案例；
- 需要展示参考图和多个分镜结果的同屏对比；
- GEO 运营人员持续需要管理大量可公开截图。

届时图片必须默认仅供内部审核，只有单独勾选“允许公开”后才能进入公开页面；实现仍不得擅自修改 COS 桶权限。

## 6. 内容生产与发布流程

1. 在问题库录入 5 至 15 条人物一致性相关问法，并选择目标平台。
2. 在证据库录入 `/assets`、`/projects`、`/script` 能支持的事实，完成公开性和事实边界审核。
3. 创建一个指南内容项，slug 使用 `ai-character-consistency`。
4. 将多个问题和已审核证据关联到同一草稿。
5. 生成或人工整理结构化正文。
6. 运行确定性质检和模型审查，处理无依据绝对化表述、重复内容、证据缺口和内部链接问题。
7. 人工提交审核并发布。
8. 发布后通过匿名浏览器检查详情页、canonical、结构化数据和站点地图。

模型不得绕过人工审核直接发布。

## 7. 失败与边界处理

- 来源页需要登录：证据不批准，改用现有公开产品页或先建设公开内容。
- 来源页只能证明宽泛能力：降低公开表述强度，不把“支持复用素材”推断成“保证一致”。
- 多个问题高度相似：继续关联同一主题页，不创建重复页面。
- 问题意图发生变化：另建案例或报告，但必须具有不同证据和独立正文价值。
- 没有真实实测材料：不发布成功率、对比结果和效果排名。
- GEO 公开路由尚未部署：不把本地验收地址当成已上线证据，先完成部署再提交索引。

## 8. 验收标准

发布第一篇内容后必须满足：

- `/guides/ai-character-consistency` 匿名访问返回 200；
- 已登录和未登录访问均显示同一篇公开文章，不跳转工作台；
- 原始服务端 HTML 包含完整标题、摘要、H1、正文和结构化数据；
- canonical 指向正式 HTTPS 地址；
- 页面进入 `sitemap.xml` 并具有真实 `lastmod`；
- 页面关联多个人物一致性问题，而不是每个问题生成重复页面；
- 页面引用的事实均由已审核公开证据支持；
- 页面不包含绝对一致、保证效果、无依据比例或排名；
- 页面不包含私有项目 ID、用户素材或需要登录的证据地址；
- 第一版后台没有新增图片上传入口；
- COS 配置、桶权限和存储访问方式保持不变。

## 9. 测试方式

- 服务测试：公开详情路由、列表路由、404、发布后站点地图、归档后的 301/410。
- 内容测试：多问题关联同一版本、未审核证据阻断、绝对化表述阻断、重复内容阻断。
- gstack 验收：匿名访问页面，检查标题、正文、canonical、JSON-LD、网络失败请求和控制台错误。
- 回归测试：现有六个公开产品页、登录后工作台和后台 GEO 运营入口保持原有行为。

## 10. 非目标

本阶段不包含：

- GEO 图片上传；
- COS 或其他对象存储改造；
- 私有项目公开分享；
- 自动登录抓取或模拟用户会话；
- 每条问题自动生成独立页面；
- 无人工审核的自动发布；
- 平台收录结果保证。
