# 新手引导时间线与安全目标扩展设计

## 目标

把现有“核心步骤在上、所有提示步骤堆在完成卡片后”的后台配置页改为真实执行顺序的时间线编辑器。管理员可以在核心节点之间新增、移动和排序提示步骤，并从当前页面已经登记的多个安全目标中选择高亮位置。

本次只增强提示步骤的编排能力。首次登录资格、核心步骤、业务动作、完成条件和最多 12 个提示步骤的限制保持不变。

## 当前问题

1. 后台把 `tips` 数组统一渲染在全部核心卡片之后，视觉顺序与前台执行顺序不一致。
2. 运行时只支持“创建项目前、进入项目前、生成分镜前”三个插入点，无法表达“分镜生成完成后、确认预览前”或“确认提交后、完成卡片前”。
3. 每个插入点目前只登记一个目标，“指引目标”下拉框没有实际选择空间，却给管理员造成可以自由选择的错觉。
4. 提示步骤只能在同一插入点内上下移动，后台缺少一张可以快速核对完整引导顺序的视图。

## 推荐交互

后台左侧改为一条固定核心步骤与可变提示步骤混排的时间线：

```text
欢迎卡片
  ＋ 创建项目前添加提示
核心步骤 · 创建项目
  ＋ 进入项目前添加提示
核心步骤 · 进入项目
  ＋ 准备剧本前添加提示
核心步骤 · 准备剧本
  ＋ 生成分镜前添加提示
核心步骤 · 生成分镜
核心步骤 · 生成处理中
  ＋ 生成完成、确认预览前添加提示
核心步骤 · 确认预览
  ＋ 确认提交、完成卡片前添加提示
完成卡片
```

每个插入点提供自己的“添加提示”按钮。新增提示默认属于该插入点，并立即出现在对应位置，不再追加到页面末尾。

提示卡片保留眉题、标题、说明、按钮文案、删除和排序能力，并作以下调整：

- “出现时机”可以把提示移动到另一个插入点；移动后卡片立即在时间线中换位。
- 同一插入点内使用上移、下移排序，不跨核心步骤交换。
- 当前插入点只有一个可用目标时，显示只读的“指引目标：xxx”，不渲染无意义的下拉框。
- 当前插入点有多个目标时，显示目标下拉框。
- 目标切换后，右侧预览同步显示目标名称、所在页面和提示卡片效果。
- 页面顶部增加紧凑的“执行顺序”摘要，保存前可直接核对所有核心步骤和提示步骤的真实顺序。

## 插入点

继续使用“进入下一个核心步骤之前”的语义，避免 `after-*` 在失败、返回和重试流程中产生歧义：

| 配置键 | 后台名称 | 触发时机 |
| --- | --- | --- |
| `before-create-project` | 创建项目前 | 欢迎卡片点击开始后 |
| `before-enter-project` | 进入项目前 | 项目创建成功后 |
| `before-prepare-script` | 准备剧本前 | 新项目打开并加载完成后 |
| `before-generate-storyboard` | 生成分镜前 | 用户选择示例剧本或自己的剧本后 |
| `before-confirm-storyboard` | 生成完成、确认预览前 | AI 分镜结果准备完成后 |
| `before-complete` | 确认提交、完成卡片前 | 分镜提交成功并进入分镜工作台后 |

“生成处理中”不开放插入提示。模型运行期间只保留状态反馈，避免提示卡片打断等待体验。

## 安全目标目录

管理员仍不能输入 CSS 选择器、DOM ID 或动作名。代码维护稳定的目标键、中文名称、适用插入点和可选业务动作。目标通过语义化 `data-first-login-target` 标记定位，页面样式或 DOM 层级变化不影响后台配置。

首期目标目录：

| 插入点 | 可选目标 |
| --- | --- |
| 创建项目前 | 项目模块入口、创建项目按钮 |
| 进入项目前 | 刚创建的项目卡片 |
| 准备剧本前 | 剧集模块入口、创建第一集按钮 |
| 生成分镜前 | 剧本输入区、文本模型选择、提示词技能选择、AI 生成分镜按钮 |
| 生成完成、确认预览前 | 分镜预览区域、场景表、角色表、道具表、分镜表、创建章节按钮 |
| 确认提交、完成卡片前 | 分镜工作台、刚创建的第一条分镜 |

目标注册项包含：

```ts
interface FirstLoginOnboardingTarget {
  key: string;
  label: string;
  placements: readonly FirstLoginOnboardingPlacement[];
  pageLabel: string;
  action?: string;
}
```

`action` 只用于已有可点击目标。非操作型区域只负责高亮，用户通过提示卡片的“下一步”继续。

## 配置与兼容性

现有 `creator.first_login_onboarding` 配置结构保持不变，仍使用有序 `tips` 数组：

```ts
interface FirstLoginOnboardingTip {
  id: string;
  placement: FirstLoginOnboardingPlacement;
  targetKey: FirstLoginOnboardingTargetKey;
  eyebrow: string;
  title: string;
  description: string;
  primaryButton: string;
}
```

无需数据库迁移。已有三个插入点及其提示继续有效，后台读取后按 `placement` 自动放入时间线对应位置。数组顺序仍是同一插入点内的执行顺序。

后端继续返回插入点和安全目标目录。保存时同时校验插入点存在、目标存在且目标属于该插入点；非法组合不会进入公开配置。前端保留同样的白名单校验，防止旧缓存或异常数据绕过后端。

## 前台状态流转

前台把“进入核心步骤”统一处理为：

1. 根据即将进入的核心步骤找到对应插入点。
2. 按配置顺序查找该插入点尚未完成的第一条提示。
3. 有提示则进入 `tip` 状态，保存 `nextStep`；无提示则进入核心步骤。
4. 点击提示卡片“下一步”或符合登记动作的高亮目标后，继续同一插入点的下一条提示。
5. 同一插入点全部完成后进入 `nextStep`。

新增映射：

- `project-opened` 进入 `prepare-script` 前运行 `before-prepare-script`。
- `generation-ready` 进入 `confirm-storyboard` 前运行 `before-confirm-storyboard`。
- `storyboard-committed` 进入 `complete` 前运行 `before-complete`。

关闭剧集编辑器、关闭预览、生成失败等现有返回路径保持原行为；只清理当前页面不再适用的提示状态，不把用户推进到错误的核心步骤。

## 目标不存在时的处理

目标可能因为权限、数据为空或页面改版暂时不在 DOM 中。新手引导不能因此卡死：

- 渲染后检查当前目标是否存在且可见。
- 目标不存在时自动标记该提示为已跳过，并继续同一插入点的下一条提示。
- 连续跳过最多 12 次，避免异常配置形成循环。
- 跳过仅影响当前用户本次引导，不修改后台配置。
- 开发环境记录目标键和插入点警告，生产环境不向用户展示技术错误。

## 管理后台预览与校验

右侧保留卡片预览，并增加当前上下文信息：

- 出现时机；
- 所在页面；
- 高亮目标；
- 当前提示在同一插入点内的序号。

保存前后台表单检查每条提示的必填字段和目标组合。服务端仍是最终校验来源。保存失败保留草稿并把错误定位到具体提示卡片；保存成功后使用服务端规范化结果重新渲染时间线。

## 修改范围

- 后端：扩充插入点与目标目录，保持现有接口和配置键。
- 管理后台：将固定核心区与提示区改为时间线混排，增加按插入点新增和条件式目标选择。
- 前台：扩充核心步骤到插入点映射、目标标记和目标缺失跳过处理。
- 测试：覆盖旧配置兼容、新插入点、多个目标、同位置排序、跨位置移动、目标缺失跳过及完整首次登录流程。

不修改首次登录判断、短信登录、团队成员排除规则、核心业务动作、分镜生成接口或数据库结构。

## 验收标准

1. 后台看到的时间线顺序与新用户实际经历顺序一致。
2. 可以在“生成完成、确认预览前”和“确认提交、完成卡片前”新增提示。
3. 生成分镜前至少可选择剧本输入区、文本模型、提示词技能和生成按钮。
4. 生成完成后至少可选择预览区域、四类结果表和创建章节按钮。
5. 单目标位置不显示下拉框，多目标位置可以正常切换。
6. 旧提示配置无需迁移且执行顺序不变。
7. 目标缺失不会卡住新手引导。
8. 非新用户、团队成员以及跳过引导的行为不变。

## 非目标

- 不允许删除、拖动或重新定义核心步骤。
- 不开放任意 CSS 选择器、URL、脚本或业务动作。
- 不做按用户分群、灰度、定时发布和多语言。
- 不把新手引导扩展成通用工作流引擎。
