# 首页缓存与及时更新设计

## 目标

只优化首页，不改变项目、资产库、画布、导演台等其他模块的接口或行为。

- 首页刷新时先显示浏览器持久缓存中的推荐内容。
- 后台修改首页背景、分类或推荐视频后，已打开的首页在 15 秒内更新。
- 同一媒体版本的背景视频在配置的签名缓存窗口（最多 7 天）内刷新时复用浏览器缓存，不重复下载 COS 对象。
- 媒体版本发生变化时立即切换到新 URL，不继续使用旧视频。

## 当前问题

- 首页推荐数据只存在进程内 5 分钟缓存，完整刷新不能先显示上一次内容。
- 内存缓存命中后的静默刷新不会把新结果推回当前首页。
- 背景视频网关的 307 只缓存 5 分钟，过期后新签名 URL 会形成新的浏览器缓存键，导致同版本对象被再次下载。
- 媒体 URL 已使用 `updatedAt` 作为版本，这是正确的缓存失效基础，应保留。

## 推荐架构

### 推荐数据

浏览器使用版本化的 localStorage 记录最近一次有效的首页推荐 payload。工作台初始化时同步读取并立即填充 `homeBackground` 和 `homeTvCategories`，随后发起一次强制校验请求。

`GET /api/home-recommendations` 返回稳定 ETag，并使用 `Cache-Control: public, max-age=0, must-revalidate`。浏览器在 15 秒轮询、窗口重新可见、重新进入首页时进行条件校验。内容未变化时复用缓存响应；内容变化时返回新 payload，立即更新页面和 localStorage。

轮询仅在首页可见时运行。页面隐藏或用户离开首页时不产生轮询请求。并发校验继续使用现有 surface AbortController，旧响应不得覆盖新响应。

### 背景视频

媒体缓存键继续使用带 `?v=<updatedAt>` 的同源版本 URL。同版本 URL 长期不变，新版本 URL 必然变化。后台上传时已给 COS 对象写入一年 `immutable` 缓存头；网关继续 307 直出 COS 并保留 Range 能力，避免把冷流量和长连接压到 Node 应用进程。

读取顺序：

1. 先复用已有 Cache Storage 条目和当前页面已缓冲的 video 元素。
2. 未命中时直接使用版本 URL 播放，保持 COS 直出与最快首帧。
3. 背景视频签名和同源 307 使用 `HOME_BACKGROUND_MEDIA_SIGNED_URL_EXPIRES_SECONDS`（最多 7 天，未配置时继承通用签名时长）；同版本刷新复用相同签名 URL 及 COS 对象的浏览器 HTTP 缓存。
4. 后台更新产生新的 `?v=`，浏览器立即请求新版本，不把旧内容缓存到新键下。

离开首页时继续暂停并保留现有 video 元素和 `src`；返回首页复用已经缓冲的元素。只有版本 URL 变化时才清理旧 object URL 并加载新视频。

## 失败与降级

- localStorage 不可用或数据损坏：忽略持久缓存，继续请求接口。
- 条件校验失败：保留最近一次有效内容，不清空首页。
- Cache Storage 不可用：直接使用版本 URL，依赖标准浏览器 HTTP 缓存。
- 后台返回空背景或 inactive：立即停止旧视频并展示现有静态背景。

## 验收标准

- 冷启动：缓存为空时首页功能与当前一致，视频可以直接开始加载。
- 热刷新：缓存内容立即展示，后台校验在异步执行。
- 无更新：15 秒校验不改变 DOM，不重新设置视频 `src`。
- 有更新：15 秒内替换推荐内容；背景版本变化时只请求新版本。
- 同版本热刷新：配置的签名缓存窗口内复用相同重定向和 COS HTTP 缓存，不重新下载对象。
- 离开再返回：首页视频元素继续复用，不移除 `src`，不重新 load。

## 范围边界

- 不引入 Service Worker。
- 不修改首页视觉、自动播放规则或推荐排序。
- 不改 COS 上传接口、存储适配器或业务数据结构。
- 不处理媒体转码、封面格式或其他模块性能。
