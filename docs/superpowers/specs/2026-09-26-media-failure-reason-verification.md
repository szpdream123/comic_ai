# 媒体失败原因与参数确认复核

## 真实失败原因

本次失败任务 `e4735df7-23f9-41a3-9f9e-02412d649efc` 的已存在供应商任务经只读查询，返回：

```json
{"status":"failed","error":"Input data is suspected of being involved in IP infringement"}
```

含义是供应商认为输入内容疑似涉及知识产权侵权。平台不能据此推断具体是哪张参考图或哪个词触发。

适配器只读取 `error.message`，遗漏字符串 `error`，导致 worker 收到的 providerMessage 为空，最终变成通用视频生成失败文案。另外，原始响应附着在不可枚举的 Symbol 上，终态保存前对象展开丢失该属性，数据库保留了上次 processing 响应。

## 本次修改

- 适配器支持字符串、嵌套 error 和 failure_reason，保留既有读取路径。
- 添加知识产权错误的中文解释；明确的未知 providerMessage 保留具体原因，隐藏凭据与链接，限制长度，拒绝整页 HTML/整段 JSON 作为公开文案。
- 保留 providerMessage 字段语义，防止持久化的二次翻译把未知英文原因再次改成通用提示。
- 原始供应商响应在对象展开前转换为可保存字段，修复最终失败响应丢失。沿用现有 provider_requests 记录，没有新增业务日志体系。
- 不改写历史任务、聊天消息或供应商生成结果。

## 参数确认复核

历史失败请求实际发送 15 秒、16:9、720P，未发现参数确认记录。用户截图仍显示旧“返回主页”；刷新后的本地页面显示“返回画布”。旧页面仍运行旧模块是较强推断，无法仅由截图证明其全部加载版本。

通过真实画布输入框输入“请生成一个15s的视频”，用受控文本模型 SSE 返回 media_generate 工具调用，验证完整会话执行到实际确认卡片：

- 工具即使自行补了 16:9 和 720P，确认卡仍保留 15 秒、将比例与分辨率留空。
- 未选择时任务 waiting_approval，确认按钮禁用，没有视频请求。
- 选择 Wan3.0、9:16、1080P 并确认后，实际生成 HTTP 请求为 model=wan3.0-r2v、duration=15、aspectRatio=9:16、resolution=1080P。
- 所有付费请求均在浏览器内拦截，没有真实生成或扣费。本次未修改已实现的参数确认逻辑。
- 页面证据：`.local/media-failure-investigation/parameter-confirmation-live.png`。

## 验证结果

- 供应商适配器与错误处理：35 项通过。
- 前端参数、批量执行、视频契约、失败暂停：46 项通过。
- 新增 PostgreSQL 终态响应与未知原因持久化回归：通过。
- 扩展生命周期测试：12 项通过，1 项既有测试失败。失败用例 binds a pre-created model log to the worker attempt when it becomes known 直接引用不存在的 attemptId，触发 user_model_request_logs_attempt_id_fkey；未改动其业务代码或用例。
- 独立审查发现的二次翻译与引号敏感键脱敏问题已修复并复核。
- 生产运行包构建完成；本地 4310 服务及生成 worker 已重启，HTTP 200。构建仍有原有重复对象键告警。

使用当前逻辑需刷新已经打开的画布页面；重启服务不会替换浏览器内存中已加载的 JavaScript 模块。

## 合入主干前复核

在基于远程 main 的隔离工作区中复核本次完整改动。前端、队列与静态资源启动回归共 88 项通过，数据库死锁/安全重试与非思考模式请求传递共 6 项通过，前后端生产构建通过（保留上述存量告警）。

生命周期扩展测试发现工厂自身文案在持久化时也会被加上“供应商返回”前缀，现已通过精确匹配工厂已知文案保持重复翻译稳定；未知供应商原因仍保留并脱敏。旧 attempt 绑定测试已补齐真实 workflow/task/attempt 测试数据，未改变业务外键约束。供应商错误翻译和这三项相关数据库回归均已复核。

参数提醒现支持图片和视频“使用默认参数生成”，仅补齐未设置项。合入前独立审查补充验证了无比例控件的视频模型、非通用模型兼容路径，以及真实工具 schema 不接受 undefined 占位参数的边界。
