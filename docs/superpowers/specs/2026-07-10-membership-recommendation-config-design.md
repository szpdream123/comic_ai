# 会员套餐推荐配置设计

## 目标

- 推荐标签文字由管理员逐套餐配置，可以留空。
- 默认推荐套餐由管理员指定，前端只读取后台配置。
- 任意时刻最多一个公开会员套餐是默认推荐套餐。
- 不再根据 `pro`、专业版档位、价格或套餐编码推断推荐状态。

## 数据设计

复用会员套餐已有的 `displayMetadata`，不新增表和接口：

- `recommendationLabel`: 可选字符串。去除首尾空白后为空则删除该字段，前端不展示标签。
- `isRecommended`: 可选布尔值。仅 `true` 表示默认推荐套餐，未配置或 `false` 均视为非默认。

原有 `note`、`features`、`sortOrder` 及未知展示字段必须完整保留。

## 后台行为

会员套餐编辑抽屉新增：

- “推荐标签文字”输入框，可留空。
- “设为默认推荐套餐”复选框，仅公开会员套餐生效。

保存公开套餐且 `isRecommended=true` 时，会员套餐服务在同一数据库事务中移除其他公开套餐的 `isRecommended`，再保存当前套餐，保证默认推荐唯一。取消当前套餐的默认推荐允许系统暂时没有默认推荐套餐。

## 前端行为

- 推荐标签只展示 `recommendationLabel`，空值不展示。
- 金色高亮、主按钮样式和初始默认选中只由唯一的 `isRecommended` 控制。
- 若正在创建或轮询某个会员套餐的支付订单，支付中的套餐继续优先选中。
- 若后台未配置默认推荐套餐，则按后台返回顺序选择第一个可购买套餐，但不显示推荐高亮。
- 企业版静态卡片不参与后台默认推荐。

## 边界与兼容

- 多个套餐可以分别配置标签文字，但只有一个套餐可以成为默认推荐。
- 历史套餐没有新字段时正常显示，不再出现全部专业套餐同时推荐的问题。
- 管理员可在高级 JSON 中保留其他未知字段；专用表单字段只更新自己负责的键。
- 不修改会员套餐对外接口、方法签名、枚举或数据库结构。

## 验证

- 后台表单能够读写可空标签和默认推荐标志，并保留其他展示字段。
- 后端保存新默认套餐时会在同一事务内取消旧默认套餐。
- 前端只对后台指定的唯一套餐应用推荐标签、推荐高亮和默认选中。
- 无推荐配置、标签为空、支付中套餐优先等情况均有回归测试。
