# 用户邀请奖励设计

> 日期：2026-06-30  
> 状态：待评审  
> 范围：用户唯一邀请码、邀请链接自动填码、新用户邀请绑定、新人体验权益、邀请人体验权益、充值返利比例配置、邀请明细、后台会员权益兼容  
> 非范围：现金提现、分销层级、多级返佣、自动续费、复杂活动系统、老用户补绑邀请码、前台展示内部新人权益套餐

## 1. 产品结论

邀请奖励第一版做简单闭环：每个用户注册后自动拥有一个唯一邀请码和邀请链接；新用户通过邀请链接进入登录页时，登录页自动填入邀请码；只有新用户首次注册时邀请码有效。

新用户注册成功后，系统按后台配置发放一份“新人体验权益”。邀请人也可以按后台配置获得一份体验权益或积分奖励。新用户绑定后 30 天内发生充值，邀请人获得充值额度的一定比例返利，默认比例为 3%，后台可调整。

新人体验权益必须和前台售卖会员套餐区分开。后台可以复用会员权益能力配置新人体验模板，但这类模板是内部权益模板，不进入前台会员套餐列表、支付页和公开售卖入口。

## 2. 核心规则

### 2.1 邀请码与邀请链接

- 每个主用户注册成功后自动生成唯一邀请码。
- 每个主用户可复制自己的邀请链接。
- 邀请链接格式建议：

```text
https://<app-host>/login.html?inviteCode=ABC1234567
```

- 打开邀请链接后进入登录页，并自动写入邀请码输入框。
- 用户手动输入邀请码和邀请链接带入邀请码使用同一套校验规则。

### 2.2 只有新用户有效

- 只有系统判定为“首次创建账号”的用户，邀请码才生效。
- 已存在用户通过邀请链接登录，不绑定邀请关系，不发新人权益，不给邀请人发奖励。
- 一个新用户只能绑定一个邀请人。
- 邀请关系一旦绑定成功，不允许用户自助修改。
- 禁止自己邀请自己。
- 子账号不参与邀请码生成、绑定和返利，邀请关系只在主用户之间生效。

### 2.3 新人体验权益

- 新用户通过有效邀请码完成注册后，获得后台配置的新用户体验权益。
- 新人体验权益只发一次。
- 新人体验权益可以包含：有效期、功能权限、优先队列、赠送积分。
- 新人权益不显示为可购买套餐，不出现在前台会员套餐页。
- 用户侧只展示权益结果，不展示内部模板名称。

用户侧推荐文案：

```text
新人体验权益已生效
有效期至：2026-07-07
```

不推荐展示：

```text
已开通 invite_new_user_trial_7d 套餐
```

### 2.4 邀请人注册奖励

- 新用户注册并绑定邀请码成功后，邀请人可获得后台配置的体验权益或积分。
- 邀请人注册奖励只发一次。
- 是否给邀请人发注册奖励由后台开关控制。
- 邀请人的体验权益也必须使用内部权益模板，不进入前台售卖列表。

### 2.5 新用户充值返利

- 新用户绑定邀请码后，在返利有效期内发生充值，邀请人获得返利。
- 默认返利有效期为 30 天，从邀请关系绑定成功时间开始计算。
- 默认返利比例为充值额度的 3%，后台可调整。
- 第一版建议返利发成积分，不做现金余额、提现和财务结算。
- 返利比例按订单实付金额计算，不按赠送积分、优惠前金额或会员权益标价计算。
- 充值订单退款、撤销或风控失败时，返利应不发放；如果已发放，后续需要后台人工处理或补偿记录。

示例：

```text
新用户 30 天内充值 100 元
后台配置返利比例 3%
邀请人获得 3 元等值积分
若 1 元 = 100 积分，则邀请人获得 300 积分
```

## 3. 后台配置

后台管理把权益配置拆成两个 tab：`会员权益` 和 `新用户权益`。

- `会员权益` 只管公开售卖套餐。
- `新用户权益` 只管内部体验模板、邀请奖励和充值返利。

这样前台售卖和内部发放完全分开，避免新人权益混进会员套餐列表。

### 3.1 会员权益 Tab

这个 tab 只管理公开售卖套餐。

会员权益配置需要区分公开售卖套餐和内部权益模板。

| 类型 | 用途 | 前台展示 |
| --- | --- | --- |
| 公开会员套餐 | 正常售卖，如月卡、季卡、年卡 | 显示 |
| 内部权益模板 | 新人体验、邀请奖励、运营赠送、测试权益 | 不显示 |

推荐在 `membership_plans` 上增加或表达以下概念：

| 字段 | 说明 |
| --- | --- |
| `visibility` | `public` / `internal` |
| `usage_scene` | `purchase` / `invite_new_user` / `invite_inviter` / `manual_gift` / `test` |

如果第一版希望更少字段，也可以只加：

```text
visibility = public | internal
```

前台会员套餐列表只读取：

```text
membership_plans.status = 'active'
AND membership_plans.visibility = 'public'
```

### 3.2 新用户权益 Tab

这个 tab 只管理内部权益模板和邀请奖励配置。

邀请奖励配置只允许选择：

```text
membership_plans.status = 'active'
AND membership_plans.visibility = 'internal'
```

### 3.3 邀请奖励配置项

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| 是否启用邀请奖励 | 总开关 | 启用 |
| 新用户体验权益模板 | 选择内部权益模板 | 新人体验 7 天 |
| 新用户赠送积分 | 可单独配置，也可随模板 | 30 |
| 是否给邀请人注册奖励 | 老用户邀请成功是否获得奖励 | 启用 |
| 邀请人体验权益模板 | 选择内部权益模板 | 邀请体验 7 天 |
| 邀请人赠送积分 | 邀请成功后获得积分 | 30 |
| 充值返利比例 | 新用户充值后邀请人获得比例 | 3% |
| 返利有效期 | 从邀请关系绑定成功开始计算 | 30 天 |
| 返利类型 | 第一版建议固定为积分 | 积分 |
| 积分换算比例 | 返利金额折算积分 | 1 元 = 100 积分 |
| 单个新用户返利上限 | 防止异常大额刷返利 | 可选 |
| 单个邀请人周期返利上限 | 防刷控制 | 可选 |
| 状态 | 启用 / 停用 | 启用 |

### 3.4 新人权益不进入前台展示

后台内部模板可以复用会员权益字段：

- `tier`
- `period_unit`
- `period_count`
- `gift_credits`
- `seat_limit`
- `entitlements_json`
- `priority_rules_json`

但内部模板不能出现在：

- 前台会员套餐页
- 支付弹窗套餐卡片
- 可购买套餐接口
- 用户可主动续费入口

用户侧只展示权益状态和有效期。后台可以完整展示内部模板编码、来源、发放记录和审计信息。

## 4. 推荐数据模型

### 4.1 用户邀请码

现有 `users.invite_code` 继续作为每个主用户的邀请码。

约束：

- 唯一。
- 不允许为空。
- 用户创建时自动生成。
- 不建议用户自助修改。

### 4.2 邀请关系

新增 `user_invite_bindings`，记录新用户和邀请人的一次性绑定关系。

| 字段 | 含义 |
| --- | --- |
| `id` | 绑定记录 ID |
| `invited_user_id` | 新用户 ID，唯一 |
| `inviter_user_id` | 邀请人用户 ID |
| `invite_code` | 绑定时使用的邀请码快照 |
| `bound_at` | 绑定时间 |
| `rebate_valid_until` | 返利有效期截止时间 |
| `status` | `active` / `invalid` / `revoked` |
| `metadata_json` | 入口来源、UA、IP 哈希、活动配置快照 |

关键约束：

```text
UNIQUE (invited_user_id)
CHECK (invited_user_id <> inviter_user_id)
```

### 4.3 邀请奖励配置

新增 `invite_reward_configs`，第一版只保留一条当前生效配置即可。后续需要多活动时再扩展活动维度。

| 字段 | 含义 |
| --- | --- |
| `id` | 配置 ID |
| `status` | `active` / `inactive` / `archived` |
| `new_user_plan_id` | 新用户内部权益模板 ID |
| `new_user_gift_credits` | 新用户赠送积分 |
| `inviter_plan_id` | 邀请人内部权益模板 ID |
| `inviter_gift_credits` | 邀请人赠送积分 |
| `rebate_percent` | 返利比例，如 `3.00` |
| `rebate_window_days` | 返利有效期，如 `30` |
| `rebate_credit_rate` | 金额到积分换算比例 |
| `per_invited_user_rebate_cap_minor` | 单个新用户返利上限，可为空 |
| `per_inviter_period_rebate_cap_minor` | 单邀请人周期返利上限，可为空 |
| `created_by_admin_id` | 创建管理员 |
| `updated_by_admin_id` | 更新管理员 |
| `created_at` / `updated_at` | 时间 |

配置修改只影响新绑定关系和新充值返利。已绑定邀请关系应保存配置快照，避免后台改配置影响历史解释。

### 4.4 邀请奖励记录

新增 `invite_reward_grants`，统一记录新人权益、邀请人权益和充值返利。

| 字段 | 含义 |
| --- | --- |
| `id` | 奖励记录 ID |
| `binding_id` | 邀请绑定记录 ID |
| `recipient_user_id` | 收益用户 |
| `reward_type` | `new_user_trial` / `inviter_trial` / `inviter_rebate` |
| `source_type` | `invite_binding` / `billing_order` |
| `source_id` | 来源 ID |
| `membership_period_id` | 发放会员权益产生的周期 ID，可为空 |
| `credit_ledger_entry_id` | 发放积分产生的账本 ID，可为空 |
| `amount_minor` | 返利金额，积分赠送可为空 |
| `credits` | 发放积分数量 |
| `status` | `pending` / `granted` / `skipped` / `failed` / `revoked` |
| `reason` | 跳过或失败原因 |
| `config_snapshot_json` | 发放时配置快照 |
| `created_at` / `updated_at` | 时间 |

幂等约束建议：

```text
UNIQUE (binding_id, reward_type, source_type, source_id, recipient_user_id)
```

所有发放动作都要同步进入积分明细：

- 新用户体验权益对应的赠送积分，要写入积分账本，并在积分明细中可查。
- 邀请人注册奖励对应的赠送积分，要写入积分账本，并在积分明细中可查。
- 新用户充值返利对应的积分奖励，要写入积分账本，并在积分明细中可查。
- 如果某次权益发放同时产生会员周期和积分，两边都要保留，各自进入对应明细页；积分部分必须出现在积分明细里。

## 5. 后端流程

### 5.1 邀请链接进入登录页

1. 前端读取 `inviteCode` query 参数。
2. 将邀请码写入登录页邀请码输入框。
3. 用户获取验证码并完成登录。
4. 验证码登录提交时带上 `inviteCode`。

如果是密码登录或老用户登录，邀请码只作为页面预填，不触发绑定。

### 5.2 新用户注册并绑定邀请关系

验证码验证成功后，如果本次请求创建了新用户：

1. 校验邀请奖励总开关是否启用。
2. 校验 `inviteCode` 是否存在且对应有效主用户。
3. 校验邀请人不是新用户本人。
4. 插入 `user_invite_bindings`。
5. 保存当时的邀请奖励配置快照。
6. 发放新用户体验权益和积分。
7. 按配置给邀请人发放注册奖励。
8. 返回登录成功。

如果邀请码无效，第一版推荐不阻断注册，只忽略邀请码并可返回轻提示：

```text
邀请码无效，已为你正常创建账号
```

### 5.3 发放内部体验权益

发放体验权益时复用会员周期和积分账本能力，但来源必须和付费订单区分。

推荐来源：

```text
source_type = invite_reward
source_id = invite_reward_grants.id
```

发放后用户状态可以显示“新人体验权益”或“邀请奖励权益”，不显示内部模板名称。

### 5.4 新用户充值返利

支付成功事件处理后，检查订单所属用户是否存在有效邀请绑定：

1. 找到 `user_invite_bindings.invited_user_id = order.created_by_user_id`。
2. 确认绑定状态为 `active`。
3. 确认 `order.paid_at <= rebate_valid_until`。
4. 确认订单实付金额大于 0。
5. 按配置快照计算返利：

```text
rebateAmountMinor = floor(order.amount_minor * rebate_percent / 100)
rebateCredits = rebateAmountMinor / 100 * rebate_credit_rate
```

6. 写入 `invite_reward_grants`。
7. 给邀请人发放积分账本记录。

返利发放必须幂等，重复消费支付成功事件不能重复发放。

## 6. 前端体验

### 6.1 登录页

登录页保留邀请码输入框。打开邀请链接后自动预填邀请码。

推荐行为：

- query 中有 `inviteCode` 时，自动填入输入框。
- 输入框可见，但不需要强调活动规则。
- 老用户登录成功后不弹奖励提示。
- 新用户注册成功并获得权益后，可以在进入工作台后用轻提示展示：

```text
新人体验权益已生效
```

### 6.2 用户侧邀请卡片

在用户中心或会员页增加“邀请有礼”卡片。

展示：

- 我的邀请码。
- 我的邀请链接。
- 复制链接按钮。
- 已邀请用户数。
- 有效邀请用户数。
- 累计获得积分。
- 30 天内充值返利累计。

不展示内部新人权益模板名称。

### 6.3 邀请明细

明细表字段保持简单：

| 字段 | 说明 |
| --- | --- |
| 新用户 | 手机号脱敏或用户昵称 |
| 绑定时间 | 邀请关系创建时间 |
| 新人权益 | 已发放 / 未发放 / 跳过 |
| 是否充值 | 是 / 否 |
| 返利积分 | 邀请人获得的积分 |
| 返利状态 | 已到账 / 处理中 / 已跳过 |

### 6.4 会员套餐页过滤

前台会员套餐页只展示公开售卖套餐。

不能展示：

- 新人体验模板。
- 邀请人体验模板。
- 运营手动赠送模板。
- 测试模板。

## 7. 后台体验

### 7.1 会员权益 Tab

后台“会员权益”tab 只配置公开售卖套餐：

- 公开售卖。
- 内部权益模板。

内部权益模板需要明确提示：

```text
内部权益模板不会展示在前台会员套餐和支付页，仅用于邀请、运营赠送或测试发放。
```

### 7.2 新用户权益 Tab

后台“新用户权益”tab 统一配置内部模板和邀请奖励。

管理员可以配置：

- 是否启用。
- 新用户内部权益模板。
- 新用户赠送积分。
- 邀请人内部权益模板。
- 邀请人赠送积分。
- 邀请人充值返利比例。
- 返利有效期。
- 积分换算比例。
- 上限控制。

### 7.3 用户详情

后台用户详情增加“邀请关系”区块。

如果当前用户是邀请人，展示：

- 该用户邀请码。
- 邀请人数。
- 有效邀请人数。
- 累计返利积分。
- 最近返利记录。

如果当前用户是被邀请人，展示：

- 邀请人。
- 绑定时间。
- 返利有效期截止时间。
- 新人权益发放状态。

用户侧和后台的积分明细都要能看到邀请相关发放记录，至少包含：

- 发放类型。
- 来源邀请码或邀请关系 ID。
- 发放时间。
- 赠送积分数量。
- 关联权益模板或充值订单。

### 7.4 审计与人工处理

后台配置修改、奖励发放、跳过、失败、人工撤销都需要写审计。

至少记录：

- 操作人。
- 目标用户。
- 邀请绑定记录。
- 配置快照。
- 发放结果。
- 失败或跳过原因。

## 8. 风控与边界

- 邀请码无效不阻断注册。
- 新用户只绑定一次邀请关系。
- 老用户登录不触发邀请绑定。
- 自邀无效。
- 邀请人被禁用或删除时，不发邀请人奖励。
- 被邀请用户被风控禁用时，后续充值不发返利。
- 返利只算绑定后有效期内支付成功的订单。
- 返利不按充值赠送积分计算。
- 返利不做多级传播，只给直接邀请人。
- 第一版不做现金返利和提现。
- 内部权益模板不能出现在前台可购买套餐里。

## 9. 推荐实施顺序

1. 后台会员权益模板增加公开/内部区分，前台套餐列表过滤内部模板。
2. 新增邀请奖励配置，只支持一条当前生效配置。
3. 登录页支持邀请链接自动填码。
4. 新用户注册时绑定邀请关系。
5. 发放新用户体验权益和邀请人注册奖励。
6. 支付成功后按绑定关系发放 30 天内充值返利。
7. 用户侧增加邀请卡片和邀请明细。
8. 后台用户详情增加邀请关系与返利记录。

## 10. 验收点

- 新用户通过邀请链接打开登录页，邀请码自动填入。
- 已注册用户通过邀请链接登录，不绑定邀请关系，不发奖励。
- 新用户注册成功后，只获得一次新人体验权益。
- 邀请人按后台配置获得一次注册奖励。
- 后台内部权益模板不会出现在前台会员套餐页。
- 后台调整返利比例后，新绑定关系按新配置计算，历史绑定按配置快照解释。
- 新用户 30 天内充值，邀请人获得配置比例返利积分。
